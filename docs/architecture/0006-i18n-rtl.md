# ADR-0006: i18n and RTL foundation

- Status: Accepted
- Date: 2026-08-10
- Context: The product targets English and Arabic (and Kurdish later).

## Decision

- `flutter_localizations` + `flutter gen-l10n` (ARB files under `lib/l10n/`,
  `app_en.arb` complete, `app_ar.arb` Arabic). Locale follows the device.
- Layouts use `EdgeInsetsDirectional` / `AlignmentDirectional` instead of
  hard-coded left/right so RTL (Arabic) works without redesign.
- Initial translations are English-first; Arabic covers primary UI strings and
  avoids inventing questionable medical/legal wording.
- All user-facing text goes through `AppLocalizations`; no raw backend enum
  strings are shown (they are mapped via `StatusLabels`).

## Consequences

- Adding a language = new ARB file + generated delegates.
- RTL survival is enforced by directional layout conventions from day one.
